The complete issue, every comment, all three PR feedback endpoints, sub-issue response, recent merged PRs, registry metadata and baseline/current Maven reports are preserved in `sources/`. `REQUIREMENTS.md` maps every requirement to an implementation and verification. ## Baseline and actual failures

The issue initially described unobserved post-merge CI. Its later comment and the actual [main pipeline](https://github.com/link-foundation/java-ai-driven-development-pipeline-template/actions/runs/43509168769), [security](https://github.com/link-foundation/java-ai-driven-development-pipeline-template/actions/runs/43509168700) and [policy](https://github.com/link-foundation/java-ai-driven-development-pipeline-template/actions/runs/43509168563) runs already passed at `600f3c7`. A skipped runner-recovery helper is expected when there are no unacquired jobs. Preserve the merged PR 19/20 updates and implement the conflicted PR 21 update through the shared JUnit property.

The JavaScript scripts import only Node built-ins and relative modules. There is no missing npm manifest, external npm tree or lockfile to regenerate. Running npm-check-updates/install against a fabricated manifest would add no useful dependency coverage. Node 26.13.1 is now explicit in every job that runs Node; Bun stays at its current 1.4.4 release.

Syntax checking the entire script directory revealed a real pre-existing defect: `bump-version.mjs` used `await import('fs')` inside a non-async function, so Node could not parse it. A static import fixes the root cause. The new CLI regression suite checks every script's syntax and verifies actual version/output writes, native equals syntax and invalid options. Seven handwritten option parsers were replaced with [`node:util.parseArgs`](https://nodejs.org/api/util.html#utilparseargsconfig). Existing release modes, legacy invocation, injection-safe logging, recovery and runner retry behavior remain covered by the existing suite.

The initial plugin audit checked only declared coordinates and therefore missed vulnerable transitives. OSV-Scanner 2.7.1 detects deliberately vulnerable compile/test dependencies but returns `NoPackageSourcesFound` for the same dependency inside a build plugin. The bounded reproducer in `experiments/osv-audit-gaps.mjs` creates temporary POMs and installs nothing. The supplemental audit now reads Maven's resolved project/test and plugin dependency reports, including the release signing profile, and queries OSV for every artifact/version. The report parser rejects malformed and empty reports. The failing-before and passing-after audit logs are preserved.

## Existing components considered

Actionlint 1.7.12 also predates the generally available Ubuntu 26.04 hosted label. The documented label extension in `.github/actionlint.yaml` adds exactly that label; jobs still use GitHub-hosted runners. [Existing issue 682](https://github.com/rhysd/actionlint/issues/682) and our updated issue 657 reproduction describe the mismatch. The workaround preserves all other label validation.

There are no frontend changes, Dockerfiles, Gradle/Terraform/Helm manifests or git submodules. The Actionlint image digest is the only pinned container and matches Docker Hub. Pre-commit was installed into a temporary Python 3.12 environment because PyYAML 6.0.3 has no Python 3.15 wheel on this host; this optional hook-host choice does not change the project's Java or JavaScript runtime baseline. Research collectors use only the installed Python standard library.

Three bounded batches keep each file below the 500 KiB hook limit and the PR below GitHub's 300-file diff limit without losing evidence. Run full Java clean verify sequentially with a 512 MiB Maven heap, all Node tests, syntax/size checks, latest Actionlint, the configured pre-commit hooks, OSV source and actual-resolution audits. CI verifies the same source on Linux, macOS and Windows. Preserve the default-branch SHA and passing runs, re-check all issue/PR feedback, inspect the complete PR diff and confirm current-head checks before marking PR 25 ready.

The major changeset records the Java 27 baseline change. The release workflow continues to compute the package version and update POM/Java constants together, so the unreleased source stays consistently at 0.2.0. No release is published or main merge performed during this task.
